## 2. Exercise contract

A lesson is not an exercise. A file is graded only with all of:

- learner-facing statement and explicit input format, with a worked example;
- stated signed value bounds and a stated `n` bound;
- stated output comparison rule: whitespace-tolerant line comparison, trailing
  newline irrelevant;
- starter code separate from the reference snippet;
- named failure modes, per §4;
- a constraint-sized case.

Template scripts stay marked **lesson** until given a contract.

## 3. Kadane statement (first exercise)

Given `n` followed by `n` signed integers on stdin, print the maximum sum of a
non-empty contiguous subarray. `1 ≤ n ≤ 10⁶`. Values in `[-10⁹, 10⁹]`, so the
answer needs 64 bits.

Public samples (generated by a brute-force oracle, then hand-checked):

| Input | Expected | Catches |
|---|---|---|
| `9` / `-2 1 -3 4 -1 2 1 -5 4` | `6` | nothing special; the worked example, `n` corrected to 9 |
| `5` / `-1 -2 -3 -4 -5` | `-1` | zero-reset returning 0 |
| `3` / `-5 -2 -3` | `-2` | returning the first element on all-negative input |
| `3` / `2 -1 2` | `3` | resetting on every negative element |
| `4` / `1000000000 1000000000 1000000000 1000000000` | `4000000000` | 32-bit accumulators |

Private: single element, `n = 1` with a negative, all-zero, and one `n = 10⁶` case
at the published bound from a constant generator with a known answer. Every small
case cross-checked against the oracle. The million case has tied maxima by
construction, so its answer depends only on the maximum sum, never on which window
achieves it; the statement says so. Expected `0` on all-negative input does not
exist; `0` is wrong unless a zero-sum non-empty subarray exists.

## 4. Test suites

Public sample set plus a private rejected-case suite per problem. Three random
cases are not enough. Suite must reject, at minimum, each named failure mode above.

Private fixtures live outside the static build. Verdicts return per-case status
plus sample I/O only, never hidden input or output.

## 5. Runner and verifier

- Additive `run_tests.py` flags: `--json`, nonzero exit when any case fails.
  `TEST_CASES` stays as the adapter so existing files run unchanged.
- YAML fixtures, public/private split, subprocess per case.
- One job container per submission: `--network none`, read-only rootfs, non-root,
  all capabilities dropped, `no-new-privileges`, aggregate memory and no swap,
  PID, CPU and tmp quotas.
- Per case: own stdin, fresh writable dir. After every case, normal exit included,
  a process-group SIGKILL reaps the group, then a cgroup sweep SIGKILLs any process
  still holding the case cgroup, including ones that escaped the group by calling
  `setsid`. The job supervisor is PID 1 in the container, so it also owns reaping:
  after the sweep it loops on `waitpid(-1, WNOHANG)` until no child remains. The
  dir is unmounted only when the cgroup reports empty and the supervisor has no
  unreaped children; either check failing is a case fail.
- Bounded stdout and stderr capture; output cut off beyond the cap is a verdict,
  not a hang.
- A supervisor outside the sandbox owns the overall deadline and kills the whole
  container, descendants included, on timeout, cancel, or worker failure.
- Expected outputs, verifier logic and credentials never enter the sandbox.
- Sample **Run** and graded **Submit** are separate endpoints and labels.

## 6. Host smoke test (G3)

Inputs, once the host and launcher are named in G3: recorded wall and RSS for both
reference solutions and the smoke problem, the caps they are measured against, and
whether a tenant without the Docker socket can start a job.

Sequence on the target host: build image → known-good submission accepted →
normal exit with a `setsid` grandchild, confirming cgroup empty, reaped and tmp
clean → infinite loop SIGKILLed within the deadline → known-bad submission
rejected → next job runs normally after each kill.

The smoke problem needs real work under the cap, so it is DSU at `n ≈ 10⁵` with a
fixed connect/query op mix and a known final answer. Kadane stays the first
learner exercise.
